# USB 与带外恢复

插入 USB 线不等于已经拥有备用管理通道。USB 可能只有供电，也可能让设备以 host 模式工作；只有主机实际枚举出串口、USB Ethernet/RNDIS/ECM/NCM 或调试接口，才构成可用路径。

## 验证清单

在依赖 USB 恢复前确认：

- 主机能看到对应 USB VID/PID 或串口；
- 串口参数或 USB 网络地址已经记录；
- 已实际完成一次登录或固件恢复；
- 数据线支持数据而非仅供电；
- 驱动和权限在重启后仍可用；
- 备用路径没有与主链路共享同一个电源、宿主机或网络故障点。

## 设备差异

| 设备 | 常用主路径 | 可选备用 | 最终恢复方式 |
|---|---|---|---|
| WSL | 反向 SSH | Tailscale | Windows 本机控制台 |
| Spark/Linux 工作站 | 反向 SSH | Tailscale、串口（若硬件支持） | 物理键盘显示器或管理控制台 |
| Raspberry Pi | 反向 SSH | Tailscale、UART、USB gadget（需预配置） | HDMI 加键盘或重新挂载系统盘 |
| ESP32 | Wi-Fi/MQTT/OTA | USB 串口 | 本地烧录并恢复运行时配置 |

## 烧录风险

烧录或擦除 flash 可能同时清除 Wi-Fi 凭据、NVS、设备身份和 OTA 状态。操作前先确认分区和擦除范围，备份可恢复的运行时配置，并准备本地网络重新配置方法。不要把 Wi-Fi 密码写入 Git 仓库作为所谓恢复方案。

真正的带外路径必须在主链路正常时定期演练。未经验证的 USB、UART、HDMI 或云控制台只能算候选方案，不能算现有兜底。
