# 2026-08-31 ESP32-S3 WiFi OTA 打通与踩坑

目标:给 ESP32-S3(N16R8, device_id `esp32-s3-walle`)加 WiFi OTA,首次 USB 刷入后不插 USB 也能远程升级。要求与现有模块解耦、不影响现有端云功能。

结果:**成功**。设备从 `esp32-wangyutang-v1` 经纯 WiFi OTA 升级到 `esp32-wangyutang-v2-ota` 并自动重启,全程无 USB 数据连接。

## 架构(解耦)

- **云侧零代码改动**:触发走 device_hub 现成 `ota` 命令(已在 KNOWN_ACTIONS);固件托管走 tang 网关 Caddy `file_server`(`http://110.40.154.41/fw/*.bin`,即 `robot_gateway/site/fw/`)。完全不碰 device_hub,避免与 codex 的旁路改动冲突。
- **端侧**:权威仓 `git_space/esp32_wifi` 的 `feature/wifi-ota` 分支(commit 144530d)。新增 `main/ota_updater.{h,cpp}`(自包含 esp_https_ota)、`app_main.cpp` 加 `ota` 命令分支、`partitions.csv` 改双 OTA 槽(16MB: ota_0/ota_1 各 3MB + otadata)。不动 wifi/audio/mqtt 逻辑。

## 踩过的坑(含误判过的假设)

1. **命令送不到设备(卡 dispatched)**。误判:以为走心跳回执。真相:设备 base_url=`http://110...` 走 raw-HTTP 心跳,其 raw 客户端读不到响应体(`raw recv ended errno=11 bytes=0`)→ 收不到回执命令。命令实际走 **MQTT**(broker=device-hub 容器内 `host.docker.internal:1883`,topic `devices/{id}/command/{cid}`,设备订阅 `.../command/#`,ack 在 `.../ack`)。下发用 `docker exec device-hub python + paho`,**retain=False**(retain 会在设备重启重连后重复投递 → OTA 死循环)。

2. **原生 USB-JTAG 的 DTR/RTS 复位是空操作**。误判:刷机结尾 "Hard resetting via RTS pin" + uptime 不归零 → 以为刷机没成功。真相:ESP32-S3 原生 USB-JTAG 不吃 DTR/RTS 复位。用 `esptool.py --before default_reset --after hard_reset chip_id`(USB-JTAG 专用复位)才真重启。复位后启动 banner `Loaded app from partition at offset 0x20000`(=ota_0)确证新固件在跑。

3. **命令队列被卡死**。codex 测试遗留的 play_audio 卡住,后续命令(含 ota)全排队。esptool 复位清掉瞬态队列后解除。

4. **被动串口监听抓不到日志(0 字节)**。ESP32-S3 USB-CDC 控制台 DTR/console 配置问题。绕过 → **在 broker 订阅 `devices/{id}/#` + 发命令,看 ack 的 status/message** 直接诊断,不依赖串口(强烈推荐的诊断法)。

5. **根因 `ESP_ERR_INVALID_ARG`**。ack 抓到 `failed stage=ota error=ESP_ERR_INVALID_ARG`。原因:esp_https_ota **默认拒绝纯 HTTP URL**。本 ISP 封 TCP/443 必须走 HTTP → 须开 `CONFIG_ESP_HTTPS_OTA_ALLOW_HTTP=y`(编译期,得重刷一版带此开关的固件才能生效)。

6. **wsl 刷机时 Tailscale 反复掉线**。每次自己恢复(几分钟)。有一次误导后台等待器:`while ssh ...; do` 循环里 ssh 因断网失败会退出循环,被误当成"任务完成"——写等待器时要区分"进程结束"和"连接失败"。

## 关键命令

```bash
# usbipd 转发设备到 WSL
ssh wsl '"/mnt/c/Program Files/usbipd-win/usbipd.exe" attach --wsl --busid 2-5'  # → /dev/ttyACM0
# esptool 真复位 + 看启动分区
esptool.py --chip esp32s3 -p /dev/ttyACM0 --before default_reset --after hard_reset chip_id
# 经 MQTT 下发 ota + 看 ack(诊断)
docker exec device-hub python -c '...paho: subscribe devices/{id}/# ; publish devices/{id}/command/{cid} {action:ota,args:{url}} retain=False...'
```

## 可持续性收尾(2026-09-01,已完成)

- v1→v2 首个 OTA 验证成功,但 v2 是 allow-http 开关加入前构建的 → v2 无法再 OTA。
- USB 刷入带 allow-http 的 **v3**,再做 **v3→v4 纯 WiFi OTA 一次通过(无 INVALID_ARG)**,证明从带 allow-http 的固件出发可**反复自持 OTA**。
- 设备当前 `esp32-wangyutang-v4-ota`,在线健康;usbip 已断开。
